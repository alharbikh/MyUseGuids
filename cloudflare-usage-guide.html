1. نظرة عامة

Cloudflare يجمع DNS وProxy/CDN والحماية وWorkers للحوسبة على الحافة وPages لنشر المواقع. DNS يحدد الوجهة، والProxy يمكن أن يمرر حركة HTTP/HTTPS عبر شبكة Cloudflare، بينما Workers/Pages قد تستضيف التطبيق نفسه.

3. DNS

السجلات الشائعة: A وAAAA لعناوين IP، CNAME لاسم آخر، MX للبريد، وTXT للتحقق وسياسات البريد.

  1. DNS → Records.
  2. Add record.
  3. حدد Type.
  4. أدخل Name وContent.
  5. حدد Proxy status إن كان متاحًا.
  6. راجع TTL ثم Save.
قبل التعديل: احتفظ بالقيمة القديمة وافهم أثر السجل، خصوصًا MX/TXT وProduction.

4. Proxy وSSL/TLS

الوضعالمعنى
Proxiedتمر حركة HTTP/HTTPS عبر Cloudflare، فتستفيد من ميزات الشبكة والحماية المناسبة.
DNS onlyCloudflare يجيب DNS فقط والاتصال يذهب مباشرة للهدف.
SSL/TLS: لا تغيّر وضع التشفير عشوائيًا. يجب أن يتوافق مع شهادة وإعدادات الـOrigin.

5. Workers

Workers مناسب للـAPIs وredirects وmiddleware وwebhooks والعمليات server-side الخفيفة.

npm create cloudflare@latest -- my-worker
cd my-worker
npx wrangler dev
npx wrangler deploy

يمكن إنشاء Worker أيضًا من Dashboard. يفضل بقاء مصدر المشاريع الجادة في Git.

6. Pages

Pages ينشر مواقع وتطبيقات Frontend عبر C3 CLI أو Direct Upload أو Git integration.

الطريقةمتى تستخدمها؟
Git integrationللنشر التلقائي مع كل push وPreview للفروع وPRs.
Direct Uploadلرفع build جاهز مباشرة.
CLIللنشر من terminal أو CI.
اختيار Git integration في Pages له قيود على التحويل لاحقًا إلى Direct Upload؛ حدد استراتيجية النشر مبكرًا.

7. Git Integration

Pages يدعم GitHub وGitLab، ويولد Preview deployments للفروع غير Production. Workers يدعم أيضًا تكامل Git للبناء والنشر.

نمط جيد: main للإنتاج، وفروع الميزات للPreview، وPR للمراجعة قبل الدمج.

8. Wrangler

Wrangler هو CLI الرئيسي لمنصة Cloudflare Developer Platform، ويفضل تثبيته داخل كل مشروع واستخدامه عبر npx.

npx wrangler dev
npx wrangler deploy
npx wrangler --help

9. Variables وSecrets

افصل القيم العامة عن الأسرار. لا تضع API tokens أو مفاتيح الخدمات في Git. استخدم Secrets/Variables في Cloudflare أو CI، وضع فقط أمثلة بلا قيم حقيقية في ملفات مثل .env.example.

10. Domains وRoutes

يمكن نشر Worker على workers.dev أو Custom Domain/Route. Pages يوفر نطاقًا افتراضيًا ويمكن إضافة نطاق مخصص.

  • حدد من يدير DNS.
  • تأكد من عدم تعارض السجل مع خدمة قائمة.
  • حدد هل Worker يغطي النطاق كله أم مسارًا محددًا.
  • تحقق من HTTPS بعد الربط.

11. Cache والأمان

Cloudflare يمكن أن يخزن محتوى مؤقتًا ويطبق قواعد حماية قبل الـOrigin. لا تطبق Cache واسعًا على APIs ديناميكية أو بيانات حسابات دون فهم أثره.

قاعدة عملية: static assets مرشح جيد للكاش؛ الجلسات والدفع والبيانات الشخصية تحتاج سياسات دقيقة.
