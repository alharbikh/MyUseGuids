1. نظرة عامة

Supabase منصة Backend مبنية حول قاعدة PostgreSQL كاملة. Auth وStorage وRealtime وEdge Functions تتكامل مع قاعدة المشروع نفسها.

قاعدة عملية: استخدم Dashboard للفحص والإدارة اليومية، وCLI + migrations للتغييرات التي يجب أن تبقى قابلة للتتبع في Git.

3. المشاريع والبيئات

عامل كل Project كبيئة مستقلة. يفضل فصل Dev عن Production في المشاريع المهمة.

قبل أي تغيير بعيد: تحقق من اسم المشروع، project ref، الفرع/commit المحلي، والبيئة المستهدفة. لا تفترض أن الربط المحلي يشير إلى Dev.

4. قاعدة البيانات PostgreSQL

كل مشروع يحصل على PostgreSQL كامل. استخدم Primary Keys وForeign Keys وConstraints بوضوح، وأنشئ Indexes بعد قياس الحاجة.

تجنب: تعديل Schema في Production يدويًا ثم نسيان تسجيله في migrations؛ هذا يسبب اختلافًا بين Git والبيئة الحية.

5. RLS والمفاتيح

Supabase Auth يستخدم JWT، ويتكامل مع Row Level Security لتحديد الصفوف المسموح للمستخدم بالوصول إليها.

النوعالاستخدام
Publishable/client keyمن العميل ضمن RLS صحيح.
Secret/server credentialsللخادم والوظائف الموثوقة فقط.
User JWTيمثل جلسة المستخدم وصلاحياته.
مهم: لا تضع service-role أو أي Secret خادمي داخل المتصفح أو الإضافة.

6. Authentication

يدعم البريد وكلمة المرور وMagic Link وOTP وتسجيل الدخول الاجتماعي وSSO. Authentication يثبت الهوية، وAuthorization يحدد ما يستطيع المستخدم الوصول إليه.

  1. فعّل Provider المطلوب.
  2. راجع Site URL وRedirect URLs.
  3. اضبط Email Templates وSMTP عند الحاجة.
  4. اختبر انتهاء الرموز وإعادة الإرسال.
  5. طبّق RLS بعد تسجيل الدخول.
يوجد في مستودع الأدلة دليل مستقل لإعداد بريد Supabase Auth ورموز OTP.

7. Storage

استخدم Buckets للملفات والمرفقات، وحدد من يقرأ ويرفع ويحذف عبر السياسات. لا تجعل Bucket عامًا إلا إذا كانت الملفات فعلًا عامة.

8. Edge Functions

Edge Functions هي دوال TypeScript تعمل على Supabase Edge Runtime المتوافق مع Deno، ومناسبة للـHTTP endpoints وwebhooks والتكاملات والبريد والعمليات الخادمية القصيرة.

supabase functions new hello-world
supabase functions serve hello-world
supabase functions deploy hello-world
  • حدد نمط المصادقة بوضوح.
  • خزن الأسرار في Project Secrets.
  • عالج CORS صراحة عند الاستدعاء من المتصفح.
  • اجعل العمليات Idempotent عندما يمكن تكرار الطلب.

9. CLI والتطوير المحلي

supabase init
supabase start
supabase status
supabase stop

supabase login
supabase projects list
supabase link --project-ref YOUR_PROJECT_REF

إذا ثبت CLI كاعتماد npm داخل المشروع فاستخدم غالبًا npx supabase ....

10. Migrations

supabase migration new add_feature_table
supabase db push

اجعل تغييرات Schema محفوظة في Git. إذا كانت migration مطبقة على بيئة مشتركة فلا تعيد كتابة التاريخ؛ أنشئ migration تصحيحية جديدة.

11. Logs والتشخيص

ابدأ من الطبقة الأقرب للخطأ: Auth أو Function أو Database أو API. تحقق من وصول الطلب، JWT، RLS، CORS، البيئة والSecrets بدل التخمين.

12. سير عمل آمن

  1. حدد النطاق والبيئة.
  2. نفذ محليًا في branch مستقل.
  3. شغل الاختبارات.
  4. راجع diff.
  5. افتح PR.
  6. انشر إلى Dev بعد التحقق من الهدف.
  7. نفذ اختبارًا حيًا آمنًا.
  8. وثق النتيجة.
  9. انتقل إلى Production فقط بعد الاعتماد.
