1. الفكرة الأساسية: ما وظيفة Linear؟

Linear = الخطة والحالة.   GitHub = الكود والتنفيذ.   ChatGPT/Codex = القراءة والتحليل والتنفيذ والتنسيق.

أفضل طريقة لفهم Linear هي اعتباره مركز إدارة العمل: ماذا سنفعل؟ لماذا؟ من المسؤول؟ ما الحالة؟ وما الذي ينتظر المراجعة أو الاعتماد؟ أما GitHub فهو المرجع الفني للكود والفروع والـPull Requests والـCommits والدمج.

Linear: Issue←→AI Agent←→GitHub: Branch / PR←→Review←→خالد: اعتماد

3. أهم النوافذ والأقسام

Inbox — صندوق الوارد

مكان متابعة الإشعارات، التعليقات الجديدة، الإشارات إليك، وتغيرات القضايا التي تتابعها.

Projects — المشاريع

يجمع المشروع مجموعة كبيرة من Issues لتحقيق نتيجة واضحة. المشروع الحاكم حاليًا هو SmartProDigital — الإطلاق الأول.

Issues — القضايا/المهام

الوحدة التشغيلية الأساسية. يمكن أن تكون ميزة أو Bug أو مراجعة أو قرارًا أو اختبارًا أو مهمة يدوية.

Documents — المستندات

للمعلومات الثابتة الأطول مثل سياسات العمل والمعمارية والحسابات والبيئات.

Views — طرق العرض

فلاتر محفوظة لنفس القضايا مثل جاري التنفيذ وبانتظار المراجعة ومطلوب من خالد.

6. طريقة متابعة المشروع يوميًا

  1. افتح Inbox واعرف ما تغير.
  2. افتح SmartProDigital — الإطلاق الأول.
  3. راجع Milestone الحالية.
  4. اعرض In Progress ثم In Review.
  5. افتح أحدث Issues واقرأ Description → Comments → Linked PR.
  6. راجع ما يحمل Action: خالد.
  7. في GitHub راجع PRs المفتوحة المرتبطة بالمرحلة الحالية.

11. أوامر مشتركة بين Linear وGitHub

راجع الحالة الحالية لـSmartProDigital باستخدام Linear كمصدر للخطة وGitHub كمصدر للكود. اكتشف أي تعارض بينهما ولا تعدل شيئًا.
اعرض Issues التي تقول Linear إنها In Review ثم تحقق من PR المقابل في GitHub.
ابحث عن Issues المسجلة Done بينما PR المقابل لم يُدمج في main.
ابحث عن PRs المدمجة التي لم يتم تحديث Issue المقابلة لها في Linear.
استخرج آخر تقدم حقيقي للمشروع من Linear وGitHub، وليس من المحادثات السابقة.
حدد المهمة التالية التي يمكن تنفيذها بدون تجاوز ترتيب المراحل أو الموانع.
راجع آخر تعليق في كل Issue نشطة وقارنه بحالة GitHub الحالية.
أنشئ تقرير تسليم موحد يتضمن: Issue، Status، Branch، Commit، PR، Review، Tests، Merge، Deployment، Blockers، Next Action.

12. أوامر المدير الفني

بداية جلسة

راجع الحالة الحقيقية الحالية لمشروع SmartProDigital. استخدم Linear للخطة والحالة والقرارات، وGitHub للكود والـPRs والـcommits والـreviews والدمج. اعرض المرحلة الحالية، الجاري تنفيذه، الموجود In Review، آخر التعليقات، PRs المرتبطة، الاختلافات، ما ينتظر خالد، وأفضل خطوة تالية. لا تعدل شيئًا.

مراجعة PR

راجع آخر تنفيذ للمرحلة الحالية. قارن Diff بمعايير Linear والاختبارات والملاحظات والنطاق. أعطني حكمًا واحدًا: APPROVE RECOMMENDED أو CHANGES REQUIRED أو BLOCKED. لا تعدل الكود ولا تدمج.

نهاية جلسة

أغلق جلسة العمل الحالية إداريًا دون إغلاق المرحلة تلقائيًا. راجع Linear وGitHub، وثبت ما تم، الفرع والـcommit والـPR والاختبارات وما لم يتم والموانع، ثم اجعل Status تعكس الواقع. لا تجعل Done إلا إذا تحققت معايير القبول.

تدقيق المزامنة

قم بتدقيق مزامنة SmartProDigital بين Linear وGitHub. تحقق من Status لكل Issue نشطة، PR المرتبط، Draft/Ready، Open/Merged/Closed، HEAD commit، Reviews، آخر تعليق في Linear، ووجود commit على main بعد الدمج. أخرج جدول اختلافات فقط ولا تغير شيئًا.
